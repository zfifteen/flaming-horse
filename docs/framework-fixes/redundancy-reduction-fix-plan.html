Redundancy Reduction Fix Plan

The fix track is to reduce overlapping ownership one responsibility at a time. The first target is scene validation because it is the highest-risk overlap and the best test seam for future refactoring.

Status: execution plan Updated: 2026-05-19 Audience: future Codex runs Source: redundancy audit

Execution Invariant

Do not combine cleanup targets. Each patch must extract or consolidate one responsibility, add a focused test seam, and preserve the canonical entrypoint: ./scripts/create_video.sh <project_name> --topic "...".

Preserve

Scripted phase sequence, generated-artifact boundary, local cached voice policy, repair as fallback, and deterministic state ownership.

Measure

Validation gates, repair invocations, dry-run count, render attempts, voice-cache checks, and lines removed from build_video.sh.

Stop

If a refactor changes runtime behavior without an intentional contract update, stop and split the change into extraction first, behavior change second.

Ordered Fix Sequence

Order Patch Purpose Implementation Shape Required Tests Done When
1 Extract scene validation owner. Remove the worst overlap before touching repair, prompts, or final render behavior. Add scripts/scene_validator.py with named gates and stable JSON output. Port existing parser/build-script/timing checks without adding new rules. Keep build_video.sh behavior unchanged in this first patch unless a tiny call-site adapter is needed for testability. python3 scripts/test_scene_validator.py; python3 -m py_compile scripts/scene_validator.py; existing parser and contract tests. A fixture scene can be classified without invoking the full pipeline, Manim, Grok, voice generation, or ffmpeg.
2 Route build-scene validation through the owner. Make first-pass scene creation use one validation contract. Replace duplicated build_video.sh checks in handle_build_scenes with scene_validator.py --json. Keep repair invocation and diagnostics intact. Build-scenes static test proving the validator is called; first-pass diagnostic test; bash -n scripts/build_video.sh. One scene-body failure produces one named validator gate before repair is invoked.
3 Add phase no-progress sentinel. Prevent hidden success when a phase handler returns success but state does not advance. Add a narrow sentinel around plan first. A successful handler must advance phase/index, set human review, mark complete, or return nonzero. Focused shell/static test or Python harness fixture for unchanged phase; python3 scripts/test_update_project_state.py; bash -n scripts/build_video.sh. A no-progress phase fails at the first divergence point instead of looping with stale state.
4 Centralize repair invocation. Keep repair available while making repair volume measurable and comparable. Add one invoke_scene_repair_for_gate shell wrapper or small Python command. Route live repair calls through it. Do not weaken repair and do not change repair prompts. Static test for all live repair calls using the wrapper; diagnostic JSONL shape test; existing scene-repair tests. Every repair event has scene_id, gate, reason, and attempt_count recorded by one path.
5 Centralize scene metadata resolution. Remove repeated inference for scene id, file, class, and narration key. Add scripts/resolve_scene_metadata.py returning one JSON object. Replace the build_scenes resolver first, then final-render metadata repair in a later patch. Fixture states for complete, partial, malformed, and legacy scene entries; existing state contract tests. Build-scene and final-render paths agree on the same scene metadata for the same state.
6 Consolidate state mutation operations. Make update_project_state.py the practical owner of repeated state writes. Add one narrow operation such as --mode record-error or --mode record-scene-diagnostic. Replace one repeated inline JSON mutation cluster only. python3 scripts/test_update_project_state.py; new focused test for the added mode; shell syntax check. The selected mutation appears in one Python owner and is removed from build_video.sh.
7 Centralize voice cache readiness. Stop repeated voice-cache checks and backend-neutral/Qwen-named behavior from drifting. Add scripts/ensure_voice_cache.py --check first. Replace ensure_qwen_cache_index only. Defer generation/build mode until check mode is stable. Fixtures for complete cache, missing index, missing mp3, and backend mismatch; existing TTS config and cached service tests. Final render can verify cache readiness without duplicating cache-index rules.
8 Normalize entrypoint interpreter ownership. Make helper execution match the interpreter validated by create_video.sh. In entrypoint and project-creation scripts, replace bare Python helper calls with the already resolved interpreter variable. bash -n scripts/create_video.sh; bash -n scripts/new_project.sh; static search for bare helper calls in those files; existing smoke-compatible tests. The entrypoint validates and uses the same orchestration interpreter.
9 Retire dead validation surfaces. Prevent agents from following stale validation code and patch files. After scene_validator.py is live, remove dead validation artifacts and keep stale docs from describing them as current. Contract drift sentinel; targeted rg for removed live surfaces. Only one current scene-validation path is documented and executable.
10 Split final-render verification. Make final render testable without full video production. Extract verify_scene_video.py and then record_scene_rendered or equivalent state update. Use fake media fixtures first. MP4 fixture tests with audio, without audio, and missing output; final-render static integration check. Render verification and state recording can be tested independently from Manim execution.

Patch Template For Future Codex Runs

For each patch:
1. Read AGENTS.md, USER_PREFERENCES.md, focused architecture contract, this plan, and the redundancy audit.
2. State the single responsibility being extracted or consolidated.
3. Add characterization fixtures before changing the live caller.
4. Preserve canonical entrypoint behavior.
5. Run focused tests plus syntax checks.
6. Report lines removed, owner chosen, remaining duplicate surfaces, and any behavior intentionally changed.

Non-Goals

  • Do not redesign the phase sequence.
  • Do not add a slide renderer or alternate generation mode.
  • Do not weaken scene repair while consolidating it.
  • Do not patch generated projects as a substitute for framework fixes.
  • Do not mix visual-quality prompt work with ownership extraction patches.
