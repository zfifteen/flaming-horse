Flaming Horse Framework Fix Track

First-pass scene validity is not yet the effective contract. The current system protects the outer scene shape, then relies on scaffold checks, runtime dry-runs, and repair loops to converge. The repair loop is useful containment, but it is doing too much of the quality work.

Status: active repair map Scope: framework contracts Mode: assistant analysis, script execution Updated: 2026-05-17

Operating Invariant

Script mode and assistant mode use the same deterministic pipeline. The assistant may run the canonical entrypoint, read logs, inspect generated artifacts, explain failures, and implement source-level framework fixes. The assistant must not bypass the framework by hand-authoring scenes, skipping gates, patching generated artifacts as a workaround, or assembling outputs outside the scripted process.

Canonical entrypoint ./scripts/create_video.sh <project_name> --topic "..."
Default evidence project_state.json, build.log, error.log, conversation.log, scene_qc_report.md, generated scenes, rendered media, voice cache files.
Default fix targets Orchestrator scripts, harness schemas, prompt files, parser validation, scaffold construction, deterministic validators, and voice service integration.
Default non-targets One-off edits to generated projects/<project_name>/scene_*.py, plan.json, narration_script.py, or media artifacts.

Current Failure Shape

1. Loose model output Structured JSON shape is required, but several semantic contracts are deferred.
2. Artifact written Some bad artifacts can be written before cross-artifact checks run.
3. State transition tests update_project_state.py catches missing scenes, missing narration keys, and missing voice cache later.
4. Runtime gates Bash grep checks, syntax checks, timing checks, and Manim dry-runs detect invalid scene bodies.
5. Repair loop scene_repair tries to recover after the first pass fails instead of being a rare fallback.

Working thesis: Move validity checks earlier and make phase progress explicit. The pipeline should reject invalid phase output before writing durable artifacts when the contract can be checked deterministically.

Detailed Findings

P0

No-Progress Detection In The Main Loop

Observed property Several handlers call apply_state_phase ... || true. If the artifact is invalid and the state stays on the same phase while the handler returns success, the loop can repeat without preserving a clear retry failure contract.
Failure mechanism A phase can appear operationally successful even though it produced no valid state transition. The next loop sees the same phase again, but the failure is not necessarily represented as a phase failure with actionable retry context.
Framework fix After each phase handler, compare previous phase/index/state fingerprint to the new one. If no progress occurred and the phase is not intentionally waiting for human review, return a phase failure with explicit diagnostic context.
Verification contract Create fixtures where plan.json has zero scenes, narration misses keys, and precache is skipped with no cache. Each should fail once with a clear error rather than silently re-entering the same phase.
P0

Plan Validation Allows Empty Scenes

Observed property PlanResponse.scenes is a list without a minimum length. validate_and_write_plan computes scene_count and iterates scenes, but an empty list passes that loop.
Failure mechanism A structurally valid but semantically useless plan is written. The state updater later rejects it because there are no scenes, moving the failure away from the model-output boundary.
Framework fix Enforce min_length=1 in the schema or reject not parsed.scenes in the parser before writing plan.json. Keep the error in responses_last_response.json.
Verification contract Add parser-level tests proving an empty scene list exits through semantic validation and leaves no durable bad plan.json.
P0

Narration Validation Does Not Require Plan Scene Keys

Observed property NarrationResponse.script requires a non-empty mapping, but validation does not require the mapping to cover every scene narration key from plan.json.
Failure mechanism narration_script.py can be written without keys that scaffolded scenes later import through SCRIPT["scene_XX"]. The state updater catches the mismatch after the harness has reported success.
Framework fix Load plan.json during narration artifact validation, compute required narration keys, and reject missing or extra keys according to an explicit contract.
Verification contract Add tests for missing key, empty key, placeholder value, and complete key coverage. Only complete coverage writes narration_script.py.
P1

Build-Scenes Prompt Contradiction

Observed property The build-scenes system prompt instructs the model to cite retrieved sources in inline comments. The user prompt instructs the model not to include comments.
Failure mechanism The model is asked to satisfy incompatible output rules inside the same phase. This weakens first-pass scene validity and makes repair more likely.
Framework fix Remove inline source-comment requirements from scene-body generation. If retrieval provenance is needed, record it outside scene_body in logs or diagnostics.
Verification contract Prompt compliance checks should fail if any build-scenes prompt asks for comments inside scene_body.
P1

Manim API Contract Is Mostly Post-Hoc

Observed property Invalid APIs such as unsupported FadeIn keyword patterns and old animation names such as ShowCreation are detected by bash checks and render dry-runs after scene injection.
Failure mechanism The parser writes a scene body that is syntactically valid but predictably incompatible with the local Manim runtime. The repair loop then becomes the enforcement mechanism.
Framework fix Add a deterministic prewrite scene-body validator in the harness parser. Reject forbidden imports, class definitions, comments, duplicate voiceover wrappers, invalid known API patterns, unsafe timing patterns, and scaffold marker leakage before injection.
Verification contract Unit-test each rejected pattern at parser level, then keep dry-run validation as an execution gate rather than the first semantic line of defense.
P2

Voice Backend State Is Split

Observed property The project policy describes cached Qwen voice. The example environment defaults FLAMING_HORSE_TTS_BACKEND=mlx. Runtime state checks still look under media/voiceovers/qwen/cache.json, while the mediator can route synthesis through MLX.
Failure mechanism Backend choice, cache path naming, and policy language are not owned by one contract. The system may work, but future changes can easily fix the wrong layer.
Framework fix Choose one explicit story: either Qwen-only for now, or backend-agnostic local cached voice with a neutral cache path and one state check. Rename or document legacy paths deliberately.
Verification contract One project fixture should prove the selected backend creates the cache path that update_project_state.py, render-time service lookup, and QC all expect.
P2

Interpreter Ownership Is Inconsistent

Observed property create_video.sh establishes ${PYTHON:-python3.13}, but path resolution, voice prep, and build-arg parsing still use bare python3.
Failure mechanism A run can validate one interpreter but execute helper code under another interpreter. That matters for local Manim, xAI SDK, and voice dependencies.
Framework fix Define one interpreter variable at entry and use it for all Python subprocesses in that script and child scripts where practical.
Verification contract Run an entrypoint smoke test with PYTHON pointed at a known interpreter and assert all subprocess Python calls report the same executable.
P2

Stale Or Dead Surfaces Confuse Repair Work

Observed property Some docs still point at old harness/ paths and the README still shows training in the phase chain. Prior inspection also identified dead or stray lines near the end of scripts/build_video.sh.
Failure mechanism Agents and humans form the wrong mental model before they touch code. That produces fixes against old paths or legacy phase names.
Framework fix Clean stale docs after the core contracts are fixed. Remove dead code only with a focused diff and shell syntax verification.
Verification contract A targeted stale-harness search should return only historical docs that are clearly labeled as historical.
P3

Scene QC Harness Prompt Exists But Main Path Uses Bash QC

Observed property harness_responses implements scene_qc, but build_video.sh runs deterministic scene QC directly and writes scene_qc_report.md.
Failure mechanism Two apparent owners exist for the same phase. If this is intentional, the harness phase is auxiliary or legacy. If not, the architecture is unclear.
Framework fix Decide ownership. Prefer deterministic QC as the render-blocking authority, and either remove, rename, or document LLM QC as non-blocking analysis.
Verification contract The phase docs and code should agree on whether scene_qc is script-owned or harness-owned.

Recommended Work Order

  1. Make phase progress explicit. A phase that does not advance, pause for human review, or fail clearly is a framework bug.
  2. Reject bad plan output before writing. Empty scenes are not a valid plan.
  3. Reject bad narration output before writing. Narration must cover every scene key in the plan.
  4. Resolve prompt contradictions. The build-scenes phase should have one scene-body contract.
  5. Add parser-level scene-body validation. Known forbidden constructs should be blocked before scaffold injection.
  6. Then normalize voice and interpreter ownership. These are important, but first-pass scene validity and loop progress are the tighter failure drivers.
  7. Then clean stale docs and dead surfaces. Documentation drift matters, but should follow the core contract repair.

Acceptance Standard

First-pass contract

A bad model response fails before writing durable artifacts when the invalidity is deterministic and knowable at parse time.

Progress contract

Every phase iteration advances, pauses, or fails with a durable diagnostic. No silent same-phase success.

Assistant contract

The assistant interprets the scripted framework and fixes source contracts. It does not route around the framework to manufacture a video.
